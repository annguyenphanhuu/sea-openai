1. Run from the repository root after `az login`; replace `<ACR>`, `<RG>`, `<APP>`, `<TAG>` and `<ACR_LOGIN_SERVER>` with your existing registry, resource group, Container App, image tag and registry login server; configure the app's registry pull identity first.
2. Stage only approved files with `python -m deploy.prepare_context --output runs/azure-context-<TAG>`, then build and push in Azure: `az acr build --registry <ACR> --resource-group <RG> --image sea-demo:<TAG> --file deploy/Dockerfile runs/azure-context-<TAG>`; the image embeds exactly the two release SQLite files.
3. Deploy the image: `az containerapp update --name <APP> --resource-group <RG> --image <ACR_LOGIN_SERVER>/sea-demo:<TAG> --min-replicas 1 --max-replicas 1`.
4. Configure ingress target port `7860` and runtime secret `LIVE_PRESENTER_KEY`; `SEA_INTEGRATED=1` is the image default, and SQLite runtime stays separately under `runs/` (ephemeral across replacement containers).
5. HF dataset fallback is retained: only when `SEA_RELEASE_DIR` points to an absent directory, set runtime `SEA_DATASET_REPO` and secret `HF_TOKEN` (optionally `SEA_DATASET_REVISION`); valid embedded files work offline, while invalid or partial existing files fail closed.
